## Goal

Establish a secure, observable Base Mainnet provider connection, derive the EOA wallet from the configured private key, and read wallet balances under strict safety constraints that enable modular extensions.

---

## Motivation

 M1 forms the deterministic foundation for the rebalancer. Without a verified connection and balanced state, downstream stages (quotes, approvals, swaps) cannot guarantee correctness and safety. This milestone enforces cryptographic correctness, gas reserve enforcement, and strict separation of concerns to enable safe future extensions (see `docs/MODULARITY.md`).

---

## Spec Decomposition Plan

This milestone decomposes into the following atomic specifications, designed for modular composition:

- **M1S1 — Provider & Wallet Initialization**
  - **Scope**: Load `config.json`, initialize the Base Mainnet JSON-RPC provider from `BASE_RPC_URL`, verify `chainId` equals 8453, derive the wallet using `process.env.PRIVATE_KEY`, and mask address in logs.
  - **Boundary**: Connection and signer establishment only—no balance reads, no on‑chain writes, no token interactions.
  - **Outcome**: Deterministic provider bound to Base Mainnet (chainId 8453) and a wallet whose address equals `new Wallet(PRIVATE_KEY).address`.
  - **Constraints**: Node.js v22 + ethers.js v6 + pure ESM; private key accessed ONLY via `process.env.PRIVATE_KEY`; address never logged.

- **M1S2 — Hard Gas‑Reserve Check & Balance Read**
  - **Scope**: Query native ETH balance (wei) and USDC ERC‑20 balance (normalized to 18 decimals). Enforce the hard gas reserve condition: `balance >= 0.002 ETH` (`2000000000000000` wei). All financial values MUST be `BigInt`.
  - **Boundary**: Read‑only queries against Base Mainnet—no approvals, swaps, or transaction submissions.
  - **Outcome**: Observable ETH balance (wei) and USDC balance (18‑decimal normalized). Deterministic gas‑reserve result.
  - **Constraints**: Use `BigInt` for all balances; USDC decimals normalized from 6 → 18; gas reserve constant defined in `config.json` (`minEthGasReserveWei`).
  - **Critical Safety Gate**: If balance check fails, abort execution and surface a `#GAS_RESERVE_INSUFFICIENT` status without exposing private key or wallet address. This gate is an extension point `#M1_GAS_RESERVE_CHECK` documented in `docs/MODULARITY.md`.

Each specification addresses exactly its one‑line description.
generate‑spec MUST NOT create specifications beyond this plan.

## Scope

M1 is responsible for making the following true and observable:

- A Base Mainnet provider connection (chainId 8453) initialized from the `BASE_RPC_URL` environment variable.
- An EOA wallet derived from the `PRIVATE_KEY` environment variable, with the derived address masked in all outputs.
- Reading the wallet's native ETH balance as a wei `BigInt`.
- Reading the wallet's USDC balance (contract `0x833589fCD6eDb6E08f4c7C32D4f71b54bda02913`) normalized to 18‑decimal `BigInt`.
- Verifying the native ETH balance against the hard gas reserve (`0.002 ETH = 2000000000000000` wei).
- Emitting balance + reserve results without ever exposing the private key or unmasked address.

---
## Out of Scope

- 0x Swap API v2 integration (quotes, allowance target) — M2.
- Token approvals, swap execution, or any transaction submission — M4.
- Gas estimation and transaction‑cost policy — M3.
- Hysteresis band and allocation‑drift computation — M5.
- Database persistence (runs/trades) — M6.
- n8n orchestration and Telegram alerts — M7.
- Any token beyond ETH and USDC, including their address reconciliation — M2+.
- Multi‑aggregator routing or any V2 features.

---
## Success Criteria

- [ ] Provider initialization succeeds and reports network `chainId` `8453` without error.
- [ ] Wallet address derived matches `new Wallet(PRIVATE_KEY).address` (verifiable independently).
- [ ] Native ETH balance is reported as a `BigInt` and the gas‑reserve check returns `true` when `balance >= 2000000000000000`.
- [ ] USDC balance at `0x833589fCD6eDb6E08f4c7C32D4f71b54bda02913` is reported as an 18‑decimal‑normalized `BigInt` (or `0` when absent).
- [ ] Logs and stdout contain neither the private key nor the unmasked wallet address.
- [ ] Execution aborts gracefully with status `#GAS_RESERVE_INSUFFICIENT` when the gas reserve check fails; this status is an extension point for future dynamic reserve strategies.

---
## Risks

- Public Base RPC rate‑limits; mitigate with configurable `BASE_RPC_URL`.
- Private‑key leakage; mitigate with strict logging policies and address masking.
- Stale token data in adjacent docs; M1 isolates ETH/USDC only — other tokens deferred to later milestones.
- Conflicting private‑key env‑var names; mitigate by enforcing `PRIVATE_KEY` as the authoritative name.

---
## Notes

- The wallet's derived address is deterministic from `PRIVATE_KEY`, so "address derived correctly" is verifiable independently of the provider or network.
- Gas is paid in native ETH regardless of later token representation, so M1's gas‑reserve basis is native ETH.
- Known cross‑milestone drift flags are owned by later milestone maintainers, not M1 (e.g., `config.json` allocation sums to 4700 bps — M5).
